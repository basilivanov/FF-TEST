## Корневая причина проблемы

**ContextPackager собирает контекст неправильно для роли Dev**:

1. **Фокус на правилах, а не на примерах**: 90% контекста - это ограничения и запреты, но нет примеров "как делать правильно"

2. **Отсутствие file discovery**: ContextPackager не находит релевантные файлы проекта для задачи

3. **Нет API introspection**: Не анализируется существующая архитектура API

4. **Статичный контекст**: Контекст не адаптируется под конкретную задачу

## Рекомендации по исправлению

### Критичные (Priority 1)

1. **Добавить file discovery в ContextPackager**:
```python
def discover_relevant_files_for_dev_task(self, task):
    patterns = {
        "crud": ["app/api/*.py", "app/models/*.py", "app/schemas/*.py"],
        "endpoint": ["app/api/**/routes.py", "app/api/**/*_routes.py"], 
        "auth": ["app/auth/*.py", "app/middleware/auth.py"]
    }
```

2. **Включить примеры кода**:
   - Найти 2-3 существующих endpoint'а
   - Показать паттерны схем Pydantic
   - Примеры моделей SQLAlchemy

3. **API структурный анализ**:
   - Сканировать FastAPI app для понимания архитектуры
   - Извлечь middleware и dependencies
   - Показать паттерны аутентификации

### Важные (Priority 2)

4. **Адаптивная структура контекста**:
   - Для CRUD задач: больше примеров моделей и endpoint'ов
   - Для auth задач: больше security patterns
   - Для UI задач: больше frontend примеров

5. **Технологический граф**:
   - requirements.txt analysis
   - Определение используемых фреймворков
   - Извлечение конфигурации

6. **Project topology mapping**:
   - Показать структуру app/ директории
   - Mapping между URL paths и файлами
   - Dependencies между модулями

### Дополнительные (Priority 3)

7. **Интерактивные примеры**: Показать последовательность "от задачи к коду"

8. **Context validation**: Проверка что контекст содержит необходимое для роли

9. **Debug режим**: Объяснение почему выбраны именно эти файлы

## Заключение

Текущий ContextPackager **не подходит** для эффективной работы Dev роли. Требуется серьезная доработка системы сбора контекста с фокусом на:

1. **Примеры вместо только правил**
2. **Релевантные файлы проекта** 
3. **Технологический контекст**
4. **Адаптивная структура под задачу**

Без этих исправлений Dev агенты будут работать "вслепую", что приведет к некачественному коду и многочисленным итерациям исправлений.
