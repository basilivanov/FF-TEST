# Runbook обновления уставов/промптов

## Общие положения

Этот документ описывает процедуру обновления уставов и промптов ролей, включая пересчет хэшей, обновление реестра документов и проверку в UI.

## Пошаговый чек-лист

### 1. Подготовка к обновлению

1. Определите, какие документы нуждаются в обновлении
2. Создайте ветку в репозитории для изменений
3. Проверьте текущие версии документов в `docs/doc_registry.json`

### 2. Внесение изменений

1. Отредактируйте соответствующие файлы уставов/промптов
2. Убедитесь, что изменения соответствуют структуре и формату документов
3. Проверьте, что все обязательные разделы присутствуют

### 3. Пересчет хэшей

1. После внесения изменений пересчитайте SHA256 хэши для всех измененных файлов:
   ```bash
   sha256sum agents/charters/architect.md
   sha256sum agents/prompts/architect.md
   # и т.д. для всех измененных файлов
   ```
2. Запишите новые хэши для последующего использования

### 4. Обновление doc_registry

1. Откройте файл `docs/doc_registry.json`
2. Найдите записи для измененных документов
3. Обновите поля `content_hash` и `updated_at` для каждой записи
4. Увеличьте номер версии, если это необходимо

Пример обновления записи:
```json
{
  "doc_name": "agents/charters/architect.md",
  "version": "1.1.0",  // Обновленная версия
  "content_hash": "новый_sha256_хэш",
  "updated_at": "2025-08-25T15:00:00Z"  // Текущая дата и время
}
```

### 5. Обновление конфигурационных файлов

1. Если структура промптов изменилась, обновите `configs/prompts.yaml`
2. Если изменились требования к разделам, обновите соответствующие поля

### 6. Проверка в UI

1. Запустите Admin UI
2. Перейдите в раздел "Каталог ролей"
3. Убедитесь, что:
   - Измененные документы отображаются с новыми датами
   - Хэши документов соответствуют пересчитанным
   - Содержимое документов отображается корректно

### 7. Тестирование

1. Используйте кнопку "Test Call" для каждой измененной роли
2. Проверьте, что промпты работают корректно
3. Убедитесь, что логируются правильные хэши

### 8. Коммит и пуш

1. Зафиксируйте изменения:
   ```bash
   git add .
   git commit -m "Обновление уставов/промптов для ролей: краткое описание изменений"
   git push origin имя_ветки
   ```
2. Создайте Pull Request
3. Пройдите код-ревью
4. Слейте изменения в основную ветку

## Rollback

Если после обновления возникли проблемы:

1. Найдите последний стабильный коммит:
   ```bash
   git log --oneline -10
   ```
2. Откатите изменения:
   ```bash
   git revert хэш_коммита
   # или
   git checkout хэш_коммита -- путь/к/файлу
   ```
3. Обновите doc_registry.json до предыдущего состояния
4. Пересчитайте хэши, если это необходимо

## Ссылки на логи и SSE события

### Логи

- `/api/v1/logs/tail` - последние записи логов
- `/admin/logs` - интерфейс просмотра логов в Admin UI

### SSE события

- `/api/v1/stream/events` - поток событий в реальном времени
- События для мониторинга:
  - `artifact_generated` - генерация артефактов
  - `llm_call_start/end` - вызовы LLM
  - `doc_updated` - обновление документов
  - `artifact_rejected` - отклонение артефактов

## Частые проблемы и решения

### Хэши не совпадают

1. Проверьте, что файлы не были изменены после пересчета хэшей
2. Убедитесь, что пересчет выполнен правильно:
   ```bash
   sha256sum путь/к/файлу
   ```
3. Обновите хэши в `doc_registry.json`

### Документы не отображаются в UI

1. Проверьте, что пути к файлам указаны правильно в `configs/prompts.yaml`
2. Убедитесь, что файлы существуют по указанным путям
3. Проверьте права доступа к файлам

### Ошибки при тестировании промптов

1. Проверьте структуру промпта на соответствие требованиям
2. Убедитесь, что все обязательные разделы присутствуют
3. Проверьте, что нет синтаксических ошибок в форматировании
