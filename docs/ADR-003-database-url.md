# ADR-003: Унификация конфигурации БД и режимов SQLite

- **Статус:** proposed
- **Дата:** 2025-08-22
- **Контекст:** В проекте используются разные пути к файлам БД и разные режимы SQLite, что затрудняет конфигурирование и поддержку. Необходимо унифицировать работу с БД.
- **Решение:**
  - Ввести единый ключ ENV `DATABASE_URL` для основного приложения и `INDEX_DATABASE_URL` для индексатора.
  - Использовать только абсолютные пути к файлам БД: `/opt/feature-factory/data/{test|prod}.db`.
  - Установить стандартные режимы SQLite: `PRAGMA journal_mode=WAL`, `synchronous=NORMAL`, `busy_timeout=5000`.
  - Запретить использование in-memory баз данных в продакшене и тестировании.
  - Определить политику прав доступа к файлам БД (пользователь `feature`).
- **Почему так:** Унификация конфигурации упростит развертывание, повысит надежность и упростит отладку. Использование WAL режима SQLite улучшит производительность при параллельном доступе. Запрет in-memory БД в продакшене и тестировании повысит надежность и предсказуемость.
- **Альтернативы:**
  - Продолжать использовать разрозненные конфигурации (приводит к сложности поддержки).
  - Использовать PostgreSQL вместо SQLite (увеличивает сложность развертывания).
- **Последствия:**
  - Необходимость обновления кода для использования единого источника конфигурации БД.
  - Необходимость обновления документации по конфигурации БД.
  - Улучшение надежности и производительности работы с БД.
- **Риски:**
  - Возможные проблемы с совместимостью при переходе на новые пути к файлам БД.
  - Необходимость изменения существующих скриптов и конфигурационных файлов.
