# Политика бюджетов по ролям v2

## Суточные лимиты по ролям

| Роль       | Лимит токенов/день | Приоритет |
|------------|-------------------|-----------|
| Dev        | 500,000           | Высокий   |
| QA         | 300,000           | Средний   |
| Scribe     | 200,000           | Средний   |
| Architect  | 1,000,000         | Высокий   |
| Maintainer | 500,000           | Высокий   |

## Поведение WAIT_BUDGET

Когда роль превышает свой суточный лимит токенов:
1. Задача переводится в состояние `WAIT_BUDGET`
2. В логах фиксируется событие `llm_budget_exceeded`
3. Задача остается в очереди до следующего дня или до ручного перевода

Пример события в логах:
```
{
  "event": "llm_budget_exceeded",
  "role": "Dev",
  "daily_limit": 500000,
  "used_tokens": 500050,
  "task_id": "task_12345"
}
```

## Перекидывание на override

Для срочных задач, которые необходимо выполнить несмотря на превышение бюджета:
1. Можно использовать параметр `provider_override` в задаче
2. Это позволяет принудительно использовать определенного провайдера
3. Использование override логируется отдельно

Пример использования override:
```yaml
task:
  id: "URGENT-001"
  role: "Dev"
  provider_override: "gemini"  # Принудительное использование Gemini
```

## Сигналы/события llm_call_end с usage

Каждый вызов LLM должен завершаться событием `llm_call_end` с информацией об использованных токенах:

```
{
  "event": "llm_call_end",
  "role": "Dev",
  "provider": "qwen",
  "model": "qwen-max",
  "prompt_tokens": 1200,
  "completion_tokens": 2800,
  "total_tokens": 4000,
  "cost": 0.012,
  "task_id": "task_12345"
}
```

## Мониторинг и отчетность

### Ежедневный отчет
- Сводная статистика по использованию токенов по ролям
- Список задач, переведенных в WAIT_BUDGET
- Использование override провайдеров

### Еженедельный отчет
- Динамика использования токенов по ролям
- Эффективность распределения бюджетов
- Рекомендации по корректировке лимитов

## Уведомления

### Предупреждения
- При достижении 80% суточного лимита - уведомление в логах
- При достижении 95% суточного лимита - уведомление в логах и на почту администратора

### Ошибки
- При превышении 100% суточного лимита - перевод задачи в WAIT_BUDGET
