# API-Orchestrator-002-Resume.md: Контракт идемпотентного resume для /features/{id}/run

## Обзор

Этот документ описывает контракт для идемпотентного возобновления выполнения графа фичи через эндпоинт `POST /api/v1/orchestrator/features/{id}/run`.

## Требования

1.  **Единственный активный run**: Для каждой комбинации `(feature_id, env)` может существовать только один активный run одновременно.
2.  **Идемпотентность resume**: Повторный вызов `POST /features/{id}/run` при существующем активном run должен возвращать идентификатор существующего run без создания нового.
3.  **Создание нового run**: Новый run создается только если предыдущий run завершен (статус `DONE` или `FAILED`).

## Эндпоинт

### POST /api/v1/orchestrator/features/{id}/run

Запускает новый граф выполнения для фичи или возобновляет существующий активный граф.

#### Request

- **Method**: `POST`
- **URL**: `/api/v1/orchestrator/features/{id}/run`
- **Headers**:
  - `Content-Type: application/json`
  - `X-Request-ID` (опционально): для корреляции запросов
- **Path Parameters**:
  - `id` (integer): Идентификатор фичи
- **Query Parameters**: Нет
- **Request Body**: Нет

#### Response

##### 200 OK

Возвращается при успешном запуске нового графа или при возобновлении существующего.

```json
{
  "run_id": "string",
  "status": "STARTED|RESUMED"
}
```

- `run_id` (string): Идентификатор запущенного или возобновленного графа.
- `status` (string): `STARTED` если запущен новый граф, `RESUMED` если возобновлен существующий.

##### 400 Bad Request

Возвращается, если фича не находится в состоянии, допускающем запуск графа.

```json
{
  "error": "INVALID_FEATURE_STATUS"
}
```

##### 404 Not Found

Возвращается, если фича с указанным `id` не найдена.

```json
{
  "error": "FEATURE_NOT_FOUND"
}
```

##### 500 Internal Server Error

Возвращается при внутренней ошибке сервера.

```json
{
  "error": "INTERNAL_ERROR"
}
```

## Логика работы

1.  **Проверка существования фичи**: Сервер проверяет, существует ли фича с указанным `id`. Если нет, возвращается `404 Not Found`.
2.  **Проверка статуса фичи**: Сервер проверяет статус фичи. Если статус не `PLANNED` или `RUNNING`, возвращается `400 Bad Request` с ошибкой `INVALID_FEATURE_STATUS`.
3.  **Поиск активного run**: Сервер ищет активный run (статус `RUNNING` или `PENDING`) для данной фичи и окружения.
4.  **Возобновление существующего run**:
    *   Если найден активный run, сервер возвращает его `run_id` и статус `RESUMED`.
    *   Сервер может выполнить дополнительные действия для возобновления выполнения графа, например, отправить сигнал в систему управления графами.
5.  **Создание нового run**:
    *   Если активный run не найден (или предыдущий run завершен), сервер создает новый run.
    *   Генерируется новый уникальный `run_id`.
    *   Создается запись в таблице `graph_runs` с начальным статусом (например, `NEW` или `RUNNING`).
    *   Возвращается `run_id` и статус `STARTED`.

## Уникальность активного run

Для обеспечения единственности активного run, в таблице `graph_runs` должен существовать уникальный индекс на поля `(feature_id, env)` с дополнительным ограничением, что только один run для данной фичи и окружения может находиться в активном состоянии (например, статус `NEW`, `RUNNING` или `PENDING`).

Альтернативно, можно добавить булево поле `active` и создать уникальный индекс на `(feature_id, env, active=true)`, где `active` указывает, является ли run активным.

В текущей реализации необходимо добавить соответствующие проверки в приложении или миграцию базы данных для обеспечения этого ограничения.

## Журналы событий

Все вызовы этого эндпоинта логируются со следующими событиями:

- `api_call_start`: Начало API вызова.
- `api_call_end`: Завершение API вызова.
- `graph_run_started`: Создание нового графа.
- `graph_run_resumed`: Возобновление существующего графа.
- `graph_run_duplicate_prevented`: Предотвращение создания дубликата графа (если применимо).

Все логи содержат `correlation_id` для корреляции запросов.
