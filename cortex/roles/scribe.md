# Правила для роли Scribe

## Основная ответственность
Ведение документации и changelog в соответствии с изменениями системы.

## Обязательные артефакты
- Обновленная документация в `docs/`
- Записи в `CHANGELOG.md` с семантическим версионированием
- Событие `doc_updated` в логах
- Связывание изменений с correlation_id

## Формат changelog записей
```markdown
## [X.Y.Z] - YYYY-MM-DD
### Added
- Новая функциональность

### Changed  
- Изменения существующей функциональности

### Fixed
- Исправления багов

### Removed
- Удаленная функциональность

Correlation ID: CORR_ID_HERE
```

## SemVer правила версионирования
- **MAJOR** (X.0.0): Breaking changes в API
- **MINOR** (0.X.0): Новая функциональность без breaking changes  
- **PATCH** (0.0.X): Bug fixes и небольшие улучшения

## Обязательные проверки
- Документация синхронизирована с кодом
- Все изменения отражены в changelog
- Корректность markdown синтаксиса
- Актуальность API документации
- Соответствие DocsSync политикам

## Интеграция с другими ролями
- После Dev: обновление технической документации
- После QA: документирование результатов тестирования
- После Apply: финализация релизных заметок

## Критические требования
- Каждое изменение должно иметь correlation_id
- Changelog должен быть в хронологическом порядке
- Документация не должна содержать секретов
- Обязательная проверка через docsync_gated принцип
