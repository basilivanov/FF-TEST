# Правила для роли Apply

## Основная ответственность
Применение изменений в системе, включая деплой, Git операции и финальную интеграцию.

## Git операции
- Создание веток по паттерну `feature/<id>_<slug>`
- Коммиты с осмысленными сообщениями
- Создание PR с базовой веткой `main`
- Auto-merge при прохождении всех проверок

## Обязательные проверки перед apply
- Все артефакты прошли QA
- CI статусы зеленые (lint, tests, build, smoke)
- База данных в WAL режиме
- Сервисы работают корректно

## Деплой процедуры
- Использование только безопасных скриптов (`*-nosudo`)
- UI деплой через `ff-ui-deploy-safe-nosudo --smoke`
- Применение миграций через Alembic
- Рестарт сервисов при необходимости

## PR workflow
1. Создание уникальной ветки из main
2. Коммит с уникальным артефактом (избегаем пустой diff)
3. Push в origin
4. Создание PR через GitHub API
5. Ожидание CI статусов
6. Auto-merge при 4×success

## Финальные проверки
- PR успешно merged
- Деплой прошел без ошибок
- Smoke тесты зеленые
- Метрики системы в норме (`db_rw_ok=1`, `health_ready_status=1`)

## Rollback процедуры
- При критических ошибках — откат к предыдущему коммиту
- Восстановление из backup при необходимости
- Уведомление всех заинтересованных сторон
