# Security Guide

## Обзор

Этот документ описывает подход к обеспечению безопасности Feature Factory.

## Аутентификация и авторизация

### Basic Auth

Доступ к API и UI защищен Basic Auth. Учетные данные хранятся в файле `.htpasswd` в директории Nginx.

### Аутентификация пользователей

- **API**: Basic Auth через заголовок `Authorization`
- **UI**: Basic Auth на уровне Nginx

### Авторизация

На уровне приложения авторизация не реализована. Все пользователи имеют равные права.

### OAuth для LLM провайдеров (Финальный протокол)

- Источник истины: централизованно сохраненные refresh-токены провайдеров (Anthropic/Claude, Google/Gemini, Qwen, OpenAI via Codex). Первичную инициализацию выполняет `scripts/authorize_providers.py`.
- Автообновление: фоновый демон `scripts/refresh_tokens_daemon.py` получает новые access-токены по refresh-токенам каждые 30 минут.
- Сервис: `systemd`-юнит `oauth-refresh.service` (User=`feature`, `Restart=always`, `RestartSec=1800`). Логи: `/var/log/oauth-refresh.log`.
- Потребление токенов: сервисы и агенты используют только актуальные токены, обновляемые демоном; ручные команды входа/копирования токенов не допускаются.
- Запрещено: ручная аутентификация в рантайме, использование временных токенов, запуск провайдеров через `bash -lc` для получения токенов. Всегда опирайтесь на автоматический refresh.

## Шифрование

### HTTPS

Все соединения с API и UI осуществляются через HTTPS.

### TLS сертификаты

TLS сертификаты выданы Let's Encrypt и автоматически обновляются.

## Управление секретами

### Хранение секретов

Секреты хранятся в файлах окружения:
- `configs/feature-factory-test.env`
- `configs/feature-factory-prod.env`

### Переменные окружения

```bash
# API Keys
OPENAI_API_KEY=sk-***
QWEN_API_KEY=sk-***
ANTHROPIC_API_KEY=sk-ant-***

# Database URLs
DATABASE_URL=sqlite:////opt/feature-factory/data/test.db

# LiteLLM
LITELLM_BASE_URL=http://localhost:4000
LITELLM_API_KEY=none

# API Base URL (локационная независимость)
FF_API_BASE_URL=http://localhost:8081
```

### Доступ к файлам окружения

Файлы окружения доступны только пользователю `feature-factory` и группе `feature-factory`.

## Сетевая безопасность

### Whitelist доменов

Доступ к внешним API ограничен whitelist доменов:
- `api.openai.com`
- `api.anthropic.com`
- `generativelanguage.googleapis.com`
- `cdn-lfs.huggingface.co`
- `api.ozon.ru`

### Firewall

На уровне хоста настроен firewall для ограничения доступа к портам.

## Защита данных

### Маскирование чувствительных данных

В логах чувствительные данные маскируются:
- API ключи → `***REDACTED***`
- Персональные данные → `***REDACTED***`

### Хранение данных

Данные хранятся в SQLite базах данных:
- Тест: `/opt/feature-factory/data/test.db`
- Продакшен: `/opt/feature-factory/data/prod.db`

### Резервное копирование

Базы данных ежедневно бэкапятся в директорию `/opt/feature-factory/backups/`.

## Защита кода

### Sandbox исполнения

Сгенерированный код выполняется в sandbox окружении без sudo прав.

### Валидация кода

Перед выполнением сгенерированный код проходит валидацию:
- Проверка на наличие опасных операций
- Проверка на соответствие шаблонам
- Проверка на соответствие политикам

## Аудит

### Логирование действий

Все действия пользователей логируются:
- Создание/изменение/удаление фич
- Запуск задач
- Использование чата

### Формат аудит логов

```json
{
  "ts": "2023-08-21T10:30:00.123456Z",
  "level": "INFO",
  "env": "test",
  "component": "ui",
  "agent_role": "User",
  "run_id": "session-001",
  "task_id": "audit-001",
  "correlation_id": "audit-corr-abc123",
  "event": "feature_created",
  "kv": {
    "user_id": "user-001",
    "feature_id": 123,
    "feature_title": "New Feature"
  }
}
```

## Управление уязвимостями

### Сканеры уязвимостей

Регулярно запускаются сканеры уязвимостей:
- Dependabot для проверки зависимостей
- Trivy для проверки Docker образов
- Bandit для проверки Python кода

### Обновление зависимостей

Зависимости обновляются регулярно:
- Python зависимости через pip
- Node.js зависимости через npm
- Системные зависимости через apt

## Инциденты безопасности

### Процедура реагирования

При обнаружении инцидента безопасности:
1. Изолировать затронутые системы
2. Провести расследование
3. Устранить уязвимость
4. Восстановить системы из бэкапов при необходимости
5. Документировать инцидент
6. Обновить процедуры безопасности

### Контакты

При обнаружении уязвимости необходимо связаться с командой безопасности по адресу security@chococraft.ru.

## Best Practices

### Разработка

1. **Никогда не коммитьте секреты в репозиторий**
2. **Используйте файлы окружения для хранения секретов**
3. **Маскируйте чувствительные данные в логах**
4. **Проверяйте зависимости на уязвимости**
5. **Обновляйте зависимости регулярно**

### Эксплуатация

1. **Ограничьте доступ к файлам окружения**
2. **Используйте HTTPS для всех соединений**
3. **Регулярно обновляйте TLS сертификаты**
4. **Бэкапите данные регулярно**
5. **Мониторьте логи на предмет подозрительной активности**

### Аудит

1. **Регулярно проверяйте логи аудита**
2. **Анализируйте паттерны использования**
3. **Идентифицируйте аномальную активность**
4. **Документируйте все инциденты**
5. **Обновляйте политики безопасности**

## Регулирование

### GDPR

Feature Factory соответствует требованиям GDPR:
- Минимизация сбора персональных данных
- Маскирование персональных данных в логах
- Право на удаление данных

### PCI DSS

Feature Factory не обрабатывает платежные данные и не подпадает под действие PCI DSS.
