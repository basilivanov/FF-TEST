# Policy-LLM-000: Модели, бюджеты, форматы
- Роли/бюджеты: Architect ≤1800; Dev ≤1400; QA ≤800; Scribe ≤800; Maintainer ≤900; temperature=0.
- Маршрутизация: CLI-first с fallback между провайдерами; Architect/Maintainer могут быть Claude/GPT при наличии квот.
- Таймаут LLM: согласно конфигурации по ролям; 1 ретрай при нарушении формата.
- Формат ответов: см. капсулу. Код — только в fenced‑блоках.
- Учёт токенов: оркестратор ведёт счёт по ролям/суткам; при исчерпании — постановка в очередь «на завтра».

## Маршрутизация и бюджеты

### Маршрутизация
- **CLI-first** — основной транспорт для взаимодействия с LLM
- **Maintainer**: [qwen, gemini, stub]
- **Architect**: [anthropic_opus41, openai_gpt5_via_codex, gemini_25_pro, qwen_code, stub]
- **Dev**: [qwen_code, gemini_25_flash, openai_gpt5_mini, stub]
- **QA**: [qwen_code, openai_gpt5_mini, gemini_25_flash, stub]
- **Scribe**: [qwen_code, openai_gpt5_mini, stub]

### Порядок маршрутизации
1. Согласно конфигурации llm_routing.yaml для каждой роли.
2. Fallback на следующий провайдер в цепочке при ошибках (TIMEOUT, RATE_LIMIT, RC_NONZERO, JSON_PARSE_ERROR).
3. При исчерпании всех квот или превышении бюджета - постановка в очередь.

### Дневные лимиты и пороги
- **Architect**: ≤1800 токенов/день
- **Dev**: ≤1400 токенов/день
- **QA**: ≤800 токенов/день
- **Scribe**: ≤800 токенов/день
- **Maintainer**: ≤900 токенов/день

### Матрица таймаутов/ретраев
#### LLM таймауты
- **Dev/QA/Scribe**: 60s
- **Architect/Maintainer**: 120s

#### HTTP таймауты
- **Connect**: 5s
- **Read**: 30s
- **Total**: 60s

#### Ретраи
- **LLM**: 1 ретрай при нарушении формата
- **HTTP**: экспоненциальный backoff (5s, 30s, 120s)
- **Rate Limit**: линейный backoff (10s, 20s, 30s)

### Мониторинг
- Оркестратор отслеживает использование бюджетов
- При достижении порогов отправляются уведомления
- При исчерпании бюджетов задачи ставятся в очередь на следующий день
- Статистика использования токенов доступна через `/admin/tokens`
