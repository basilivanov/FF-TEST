# Ops-DB.md: Операционные процедуры для БД

## Конфигурация

### Переменные окружения

- `DATABASE_URL`: URL для подключения к основной базе данных приложения.
  - Формат: `sqlite:////absolute/path/to/database.db`
  - Пример для теста: `sqlite:////opt/feature-factory/data/test.db`
  - Пример для прода: `sqlite:////opt/feature-factory/data/prod.db`
- `INDEX_DATABASE_URL`: URL для подключения к базе данных индексатора.
  - Формат: `sqlite:////absolute/path/to/index.db`
  - Пример: `sqlite:////opt/feature-factory/data/index.db`

### Режимы SQLite

- `journal_mode=WAL`: Режим WAL (Write-Ahead Logging) для улучшения производительности при параллельном доступе.
- `synchronous=NORMAL`: Уровень синхронизации NORMAL для баланса между производительностью и надежностью.
- `busy_timeout=5000`: Таймаут ожидания блокировки 5000 мс.

## Пути к файлам

- Все файлы БД должны находиться в директории `/opt/feature-factory/data/`.
- Имена файлов:
  - `test.db`: База данных для тестового окружения.
  - `prod.db`: База данных для продакшен окружения.
  - `index.db`: База данных для индексатора.

## Права доступа

- Владелец файлов БД: пользователь `feature`.
- Группа: группа `feature`.
- Права доступа: `600` (только владелец может читать и писать).

## Запреты

- Запрещено использовать in-memory базы данных (`:memory:`) в тестовом и продакшен окружениях.
- Запрещено использовать относительные пути к файлам БД.

## Миграции

- Для применения миграций используется команда `alembic upgrade head`.
- Перед применением миграций рекомендуется сделать бэкап базы данных.

## Мониторинг

- Мониторинг доступности и производительности БД осуществляется через логи.
- Ключевые события логируются с тегами `db_upsert`, `db_replace_batch`, `db_migration_applied`.
