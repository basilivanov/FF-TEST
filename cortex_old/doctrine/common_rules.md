# ОБЯЗАТЕЛЬНЫЕ ПРАВИЛА И АНТИ-ПАТТЕРНЫ

## 🚨 КРИТИЧЕСКИЕ ЗАПРЕТЫ

### Обработка ошибок кода

**ЗАПРЕЩЕНО**: Исправлять ошибки отступов (IndentationError) или сложные синтаксические ошибки через Edit (замена строки).

**ПРАВИЛЬНО**: 
1. Сначала использовать `python -m py_compile файл.py` для точной диагностики
2. Затем `ruff check --fix файл.py` или полностью переписать файл через `WriteFile`

### Запуск приложения

**ЗАПРЕЩЕНО**: Запускать uvicorn из любой директории, кроме корня проекта (/opt/feature-factory).

**ПРАВИЛЬНО**: Всегда выполнять `cd /opt/feature-factory` перед запуском uvicorn.

### Работа с базой данных

**ЗАПРЕЩЕНО**: Создавать таблицы в БД напрямую SQL-командами.

**ПРАВИЛЬНО**: Всегда использовать Alembic для создания и применения миграций:
```bash
cd /opt/feature-factory
alembic revision --autogenerate -m "Add new table"
alembic upgrade head
```

### Управление секретами

**ЗАПРЕЩЕНО**: "Придумывать" логины и пароли или хардкодить их в коде.

**ПРАВИЛЬНО**: Запрашивать ключи секретов из `cortex/security/credentials.md` и использовать `secret_store.get_secret(key)`.

## 🔧 ТЕХНИЧЕСКИЕ ПРАВИЛА

### Импорты и зависимости

**ЗАПРЕЩЕНО**: Предполагать наличие библиотек без проверки.

**ПРАВИЛЬНО**: Всегда проверять `requirements.txt` или `package.json` перед использованием библиотеки.

### Файловые операции

**ЗАПРЕЩЕНО**: Использовать относительные пути в скриптах.

**ПРАВИЛЬНО**: Всегда использовать абсолютные пути или пути относительно корня проекта через `os.path.join()`.

### API и HTTP запросы

**ЗАПРЕЩЕНО**: Игнорировать коды статуса HTTP или не обрабатывать ошибки.

**ПРАВИЛЬНО**: Всегда проверять `response.status_code` и обрабатывать исключения.

### Логирование

**ЗАПРЕЩЕНО**: Логировать секреты или персональные данные в плейн-текст.

**ПРАВИЛЬНО**: Логировать только идентификаторы, коды ошибок и нечувствительную метаинформацию.

## 🏗️ АРХИТЕКТУРНЫЕ ПРИНЦИПЫ

### Создание новых эндпоинтов

**ПРАВИЛЬНО**: 
1. Добавить роутер в соответствующий модуль (`app/api/`)
2. Зарегистрировать роутер в `main.py`
3. Добавить корреляционные ID для трейсинга
4. Добавить валидацию входных данных

### Обработка ошибок

**ПРАВИЛЬНО**:
1. Использовать специфичные исключения (`ValueError`, `HTTPException`)
2. Добавлять контекст в сообщения об ошибках
3. Логировать ошибки с корреляционными ID

### Тестирование

**ПРАВИЛЬНО**:
1. Всегда запускать тесты после изменений: `pytest`
2. Для API тестирования использовать TestClient
3. Мокать внешние зависимости

## 🚀 ДЕПЛОЙ И CI/CD

### Сборка UI

**ЗАПРЕЩЕНО**: Использовать `npm run build` с sudo.

**ПРАВИЛЬНО**: Использовать скрипт `./bin/ff-ui-deploy-safe` для безопасной сборки.

### Проверка изменений

**ПРАВИЛЬНО**: Всегда проверять:
1. Синтаксис: `python -m py_compile`
2. Линтер: `ruff check --fix`
3. Тесты: `pytest`
4. Типы (если есть): `mypy`

### Nginx и SSL

**ЗАПРЕЩЕНО**: Изменять конфигурацию nginx без тестирования.

**ПРАВИЛЬНО**: Использовать `nginx -t` для проверки конфигурации перед reload.

## 🔄 ПРОЦЕССЫ РАЗРАБОТКИ

### Git и версионирование

**ПРАВИЛЬНО**:
1. Коммитить небольшие, логически связанные изменения
2. Писать осмысленные сообщения коммитов

**ПРАВИЛЬНО**: Проверять на:

## ⚡ ПРОИЗВОДИТЕЛЬНОСТЬ

### Запросы к БД

**ЗАПРЕЩЕНО**: N+1 запросы и отсутствие индексов.

**ПРАВИЛЬНО**: Использовать `joinedload()` в SQLAlchemy и анализировать планы запросов.

### API производительность

**ПРАВИЛЬНО**: Добавлять пагинацию для списков, кэшировать медленные вычисления, использовать асинхронные операции.
