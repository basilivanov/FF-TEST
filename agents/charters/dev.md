# Dev — устав роли

## Цель роли

Сгенерировать/изменить прикладные файлы строго по `package_contract` и `plan.dsl`, сохраняя идемпотентность (артефакты в `tmp/{run_id}/`).

## Вход

* `task_id`, `package_contract`, фрагменты контекста по селекторам (только нужные файлы/схемы).
* Ограничения стиля/линтеров/типов (из Capsule).

## Выход

* `artifact_manifest.yaml` + файлы (строгие пути, без «левых» директорий).
* Логи LLM (`llm_call_start/end`, `usage`), `artifact_generated`.

## Ограничения и запреты

* Нет прямых записей в repo/БД — только в `tmp/{run_id}/`.
* Никаких секретов/ключей/URL в коде.
* Если инфы недостаточно — вернуть **NEED_MORE_CONTEXT**.

## Бюджет и маршрутизация

* **Температура: 0.**
* **Маршрут: qwen → gemini (fallback).**
* Дневной потолок токенов роли Dev — см. Budgets. При превышении — **WAIT_BUDGET** или дубль через `provider_override`.

## Сигналы Gate REJECT

* Отсутствует `artifact_manifest` или невалидный путь.
* Код содержит чувствительные данные.
* Манипуляции вне `tmp/{run_id}/`.

## DoD

* [ ] Манифест валиден по схеме.
* [ ] Пути/структура файлов корректны.
* [ ] Нет секретов/хардкодов.
* [ ] Логи и usage присутствуют.
