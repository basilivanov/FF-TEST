# Отчет по задаче E9-RUN-RESUME-DEV

## Цель
Реализовать resume-логику в API/графе.

## Выполненные действия
1.  **Реализована логика resume в API**:
    *   Обновлен эндпоинт `POST /api/v1/orchestrator/features/{id}/run` в `app/api/orchestrator_v2.py`.
    *   Добавлена проверка на существование активного run для фичи в текущем окружении.
    *   Если активный run найден, API возвращает его `run_id` и статус `RESUMED`.
    *   Если активный run не найден, API создает новый run и возвращает `run_id` и статус `STARTED`.
2.  **Добавлено поле `env` в таблицу `graph_runs`**:
    *   Создана новая миграция `a1b2c3d4e5f0_add_env_to_graph_runs_and_unique_index.py`.
    *   Миграция добавляет поле `env` в таблицу `graph_runs`.
    *   Миграция добавляет уникальный индекс для активных run на поля `(feature_id, env)` с фильтром по статусам `NEW`, `RUNNING`, `PENDING`.
3.  **Обновлены схемы и модели**:
    *   Обновлена JSON-схема `app/api/schemas/orchestrator/R2-Run.json` для отражения нового формата ответа.
    *   Обновлена Pydantic модель `RunResponse` в `app/api/schemas/orchestrator_schemas.py`.
    *   Обновлена документация API в `docs/API-Orchestrator-001.md`.
4.  **Создан тест**:
    *   Создан файл `tests/test_run_resume.py` с тестом `test_run_resume`.
    *   Тест проверяет, что двукратный вызов `/run` для одной фичи возвращает один и тот же `run_id` и статус `RESUMED`.
    *   Тест проверяет, что API не возвращает 500 ошибок.

## Результаты
*   Эндпоинт `POST /api/v1/orchestrator/features/{id}/run` теперь детерминирован: он возвращает активный `run_id`, если run уже существует.
*   В таблице `graph_runs` создан уникальный активный индекс на `(feature_id, env)`.
*   Создан QA-тест, который подтверждает корректную работу логики resume.

## Примечания
*   В текущей реализации мок-граф в тестовом режиме не обновляет статус фичи на `DONE` после завершения. Это может быть доработано в будущем.
