# Maintainer Intake & Planning

## Рубрика классификации intent

* Класс (UI/ETL/DB/OPS/LLM-routing/Docs)
* Scope (узкий/средний/широкий), риск (низкий/средний/высокий)
* Приоритет (P1–P3)

## Поля `intent.json`

* `title`, `env`, `class`, `scope`, `acceptance`, `risks`, `depends_on`, `notes`.

## Решение

* Если недостаёт полей → **NEED_MORE_CONTEXT** (список).
* Готово → создать Feature + передать Architect.

## 5 примеров

1. **Отчёт продаж в UI**
   * Класс: UI
   * Scope: средний
   * Риск: низкий
   * Приоритет: P2

2. **Индексатор для нового источника данных**
   * Класс: ETL
   * Scope: широкий
   * Риск: средний
   * Приоритет: P1

3. **Роутер LLM для нового провайдера**
   * Класс: LLM-routing
   * Scope: узкий
   * Риск: низкий
   * Приоритет: P3

4. **Карточки пользовательских историй**
   * Класс: UI
   * Scope: узкий
   * Риск: низкий
   * Приоритет: P2

5. **Планировщик задач с приоритетами**
   * Класс: OPS
   * Scope: средний
   * Риск: средний
   * Приоритет: P2
