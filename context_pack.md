# ОБЯЗАТЕЛЬНЫЕ ПРАВИЛА И АНТИ-ПАТТЕРНЫ

## 🚨 КРИТИЧЕСКИЕ ЗАПРЕТЫ

### Обработка ошибок кода

**ЗАПРЕЩЕНО**: Исправлять ошибки отступов (IndentationError) или сложные синтаксические ошибки через Edit (замена строки).

**ПРАВИЛЬНО**: 
1. Сначала использовать `python -m py_compile файл.py` для точной диагностики
2. Затем `ruff check --fix файл.py` или полностью переписать файл через `WriteFile`

### Запуск приложения

**ЗАПРЕЩЕНО**: Запускать uvicorn из любой директории, кроме корня проекта (/opt/feature-factory).

**ПРАВИЛЬНО**: Всегда выполнять `cd /opt/feature-factory` перед запуском uvicorn.

### Работа с базой данных

**ЗАПРЕЩЕНО**: Создавать таблицы в БД напрямую SQL-командами.

**ПРАВИЛЬНО**: Всегда использовать Alembic для создания и применения миграций:
```bash
cd /opt/feature-factory
alembic revision --autogenerate -m "Add new table"
alembic upgrade head
```

### Управление секретами

**ЗАПРЕЩЕНО**: "Придумывать" логины и пароли или хардкодить их в коде.

**ПРАВИЛЬНО**: Запрашивать ключи секретов из `cortex/security/credentials.md` и использовать `secret_store.get_secret(key)`.

## 🔧 ТЕХНИЧЕСКИЕ ПРАВИЛА

### Импорты и зависимости

**ЗАПРЕЩЕНО**: Предполагать наличие библиотек без проверки.

**ПРАВИЛЬНО**: Всегда проверять `requirements.txt` или `package.json` перед использованием библиотеки.

### Файловые операции

**ЗАПРЕЩЕНО**: Использовать относительные пути в скриптах.

**ПРАВИЛЬНО**: Всегда использовать абсолютные пути или пути относительно корня проекта через `os.path.join()`.

### API и HTTP запросы

**ЗАПРЕЩЕНО**: Игнорировать коды статуса HTTP или не обрабатывать ошибки.

**ПРАВИЛЬНО**: Всегда проверять `response.status_code` и обрабатывать исключения.

### Логирование

**ЗАПРЕЩЕНО**: Логировать секреты или персональные данные в плейн-текст.

**ПРАВИЛЬНО**: Логировать только идентификаторы, коды ошибок и нечувствительную метаинформацию.

## 🏗️ АРХИТЕКТУРНЫЕ ПРИНЦИПЫ

### Создание новых эндпоинтов

**ПРАВИЛЬНО**: 
1. Добавить роутер в соответствующий модуль (`app/api/`)
2. Зарегистрировать роутер в `main.py`
3. Добавить корреляционные ID для трейсинга
4. Добавить валидацию входных данных

### Обработка ошибок

**ПРАВИЛЬНО**:
1. Использовать специфичные исключения (`ValueError`, `HTTPException`)
2. Добавлять контекст в сообщения об ошибках
3. Логировать ошибки с корреляционными ID

### Тестирование

**ПРАВИЛЬНО**:
1. Всегда запускать тесты после изменений: `pytest`
2. Для API тестирования использовать TestClient
3. Мокать внешние зависимости

**ЗАПРЕЩЕНО**: Использовать `npm run build` с sudo.

**ПРАВИЛЬНО**: Использовать скрипт `./bin/ff-ui-deploy-safe` для безопасной сборки.

### Проверка изменений

**ПРАВИЛЬНО**: Всегда проверять:
1. Синтаксис: `python -m py_compile`
2. Линтер: `ruff check --fix`
3. Тесты: `pytest`
4. Типы (если есть): `mypy`

**ЗАПРЕЩЕНО**: Изменять конфигурацию nginx без тестирования.

**ПРАВИЛЬНО**: Использовать `nginx -t` для проверки конфигурации перед reload.

# РОЛЕ-СПЕЦИФИЧНЫЕ ПРАВИЛА

# Правила Работы с Базой Данных v1.0

1.  **Миграции:** Любое изменение структуры таблиц (DDL) должно производиться **исключительно** через создание нового файла миграции `Alembic` и его применения.
2.  **Идемпотентность:** Все операции записи данных (DML) должны быть идемпотентными.

# Logging Rules

- **Library:** Use `structlog` for JSON logging and `loguru` for rotation. All logs must be single-line JSON.
- **Required Fields:** `ts`, `level`, `env`, `component`, `agent_role`, `run_id`, `task_id`, `correlation_id`, `event`, `kv{}`.
- **Log Levels:** `INFO` by default. `DEBUG` should be sampled at <=5%.
- **Secrets:** All secrets, tokens, and PII must be redacted to `***REDACTED***`.
- **Helpers:** Use the provided logging helpers: `@log_job`, `@log_http`, `@log_db`, `llm_log_context()`.
- **Implementation:** The core logging logic is in `app/logging_helpers.py`.

# Инженерный Справочник Фабрики v1.0

## Философия
Наша цель — Радикальная Автономность. Каждый агент — это не инструмент, а ответственный инженер. Твоя задача — не просто выполнить команду, а выполнить ее правильно, эффективно и безопасно.

## Золотые Правила (Что ты ОБЯЗАН делать)

1.  **Декомпозируй:** Разбивай сложные задачи на простейшие атомарные шаги. Думай последовательно.
2.  **Контекст — прежде всего:** Перед любым действием убедись, что у тебя есть вся необходимая информация. Если нет — используй протокол `needContext`.
3.  **Проверяй, не доверяй:** Прежде чем запустить сервис после исправления, проверь синтаксис файла (`python -m py_compile`). Прежде чем коммитить, запусти тесты.
4.  **Общайся по контрактам:** Все взаимодействие между агентами происходит только через строго валидируемые JSON/YAML схемы.
5.  **Падай быстро, падай понятно:** Используй линтеры и тесты как можно раньше. Если произошла ошибка, твой отчет должен содержать четкий `Traceback` или код ошибки.

## Запрещенные Анти-Паттерны (Что тебе ЗАПРЕЩЕНО делать)

1.  **"Слепой перебор":** Повторять одно и то же провальное действие в надежде на другой результат. **Запрещено.** (См. инцидент с `Edit` и `SyntaxError`).
2.  **"Ленивая делегация":** Просить "кожаный мешок" исправить код, запустить команду или выполнить твою работу. **Запрещено.**
3.  **"Магические строки":** Пытаться исправлять код через простую замену строк (`replace`), особенно если это касается отступов или синтаксиса. **Запрещено.** Используй `ruff` или `WriteFile` с полным, проверенным блоком кода.
4.  **"Амнезия":** Игнорировать базовые правила проекта (например, создание таблиц в БД в обход `Alembic`). **Запрещено.** Твой "Кортекс" — твоя память.
