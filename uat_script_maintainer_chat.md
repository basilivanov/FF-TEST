# UAT Сценарий для Maintainer Chat

## Общие положения

Этот документ описывает шаги и чек-листы для пользовательского тестирования (UAT) функциональности Maintainer Chat, которая преобразует естественный язык в задачи фич.

## Сценарий тестирования

### Шаг 1: Ввод NL-задачи в UI Chat

**Описание**: Пользователь вводит задачу на естественном языке в чат интерфейса администратора.

**Входные данные**: 
- Текст задачи: "Создай отчет о продажах в UI с возможностью фильтрации по датам и категориям товаров"

**Ожидаемый результат**:
- Сообщение успешно отправлено в чат
- Интерфейс отображает статус обработки запроса
- Через несколько секунд появляется ответ от системы

**Чек-лист**:
- [ ] Сообщение успешно отправлено
- [ ] Отображается индикатор обработки
- [ ] Получен ответ от системы
- [ ] Нет ошибок 5xx в интерфейсе

### Шаг 2: Проверка ответа Maintainer

**Описание**: Проверка корректности ответа от Maintainer, включая intent и package_contract.

**Входные данные**: 
- Ответ от Maintainer, полученный на шаге 1

**Ожидаемый результат**:
- Ответ содержит структурированный intent в формате JSON
- Ответ содержит мини package_contract
- В логах видна роль Maintainer и корректный prompt_sha256

**Чек-лист**:
- [ ] Ответ содержит поле "intent" с JSON объектом
- [ ] Ответ содержит поле "package_contract" с базовой структурой
- [ ] В логах присутствует событие с role="Maintainer"
- [ ] В логах присутствует корректный prompt_sha256
- [ ] Нет ошибок 5xx в логах

**Пример ожидаемого ответа**:
```json
{
  "intent": {
    "title": "Отчет о продажах в UI",
    "env": "test",
    "class": "UI",
    "scope": "средний",
    "acceptance": [
      "Отчет отображается в UI",
      "Фильтрация по датам работает",
      "Фильтрация по категориям товаров работает"
    ],
    "risks": [
      "Высокая нагрузка на БД при больших объемах данных"
    ],
    "priority": "P2"
  },
  "package_contract": {
    "package_id": "SALES_REPORT_UI_001",
    "summary": "Реализация отчета о продажах в UI с фильтрацией",
    "files_layout": [
      "app/api/sales_report.py",
      "app/ui/components/SalesReport.vue",
      "tests/api/test_sales_report.py"
    ]
  }
}
```

### Шаг 3: Подтверждение создания фичи

**Описание**: Подтверждение создания фичи на основе полученного intent.

**Входные данные**: 
- Intent из ответа Maintainer

**Ожидаемый результат**:
- Фича успешно создана в системе
- Статус фичи: PLANNED
- Доступна в списке фич в интерфейсе администратора

**Чек-лист**:
- [ ] Фича создана в системе (POST /api/v1/orchestrator/features)
- [ ] Статус фичи: PLANNED
- [ ] Фича отображается в списке фич в UI
- [ ] Нет ошибок 5xx при создании фичи

### Шаг 4: Запуск графа G1

**Описание**: Запуск графа выполнения задачи (G1) для созданной фичи.

**Входные данные**: 
- ID созданной фичи

**Ожидаемый результат**:
- Граф G1 успешно запущен
- Все узлы графа проходят статусы: NEW → RUNNING → DONE
- Итоговый статус: DONE
- Нет ошибок 5xx в процессе выполнения

**Чек-лист**:
- [ ] Граф G1 запущен (POST /api/v1/orchestrator/features/{id}/run)
- [ ] Узлы графа проходят корректные статусы
- [ ] Итоговый статус графа: DONE
- [ ] Нет ошибок 5xx в логах выполнения
- [ ] Время выполнения E2E в пределах нормы

## Дополнительные сценарии

**Описание**: Отправка нескольких запросов одновременно для проверки обработки нагрузки.

**Шаги**:

3. Проверить корректность каждого ответа
4. Проверить, что все фичи созданы корректно

**Чек-лист**:
- [ ] Все 3 запроса успешно отправлены
- [ ] Получены ответы на все 3 запроса
- [ ] Все ответы корректны
- [ ] Все 3 фичи созданы
- [ ] Нет ошибок 5xx

### Сценарий B: Некорректный запрос

**Описание**: Отправка запроса с недостаточно полной информацией.

**Шаги**:
1. Отправить запрос "Сделай что-нибудь"
2. Проверить ответ системы
3. Убедиться, что система запрашивает уточнения

**Чек-лист**:
- [ ] Запрос отправлен
- [ ] Получен ответ с запросом уточнений
- [ ] В ответе присутствует блок NEED_MORE_CONTEXT
- [ ] Нет ошибок 5xx

### Сценарий C: Дублирующийся запрос

**Описание**: Отправка запроса, аналогичного уже существующей фиче.

**Шаги**:
1. Создать фичу "Отчет о продажах"
2. Отправить такой же запрос повторно
3. Проверить обработку дубликата

**Чек-лист**:
- [ ] Первый запрос обработан успешно
- [ ] Второй запрос обработан с указанием существующей фичи
- [ ] Нет создания дублирующей фичи
- [ ] Нет ошибок 5xx

## Логирование и мониторинг

- [ ] В логах присутствует role=Maintainer для всех вызовов Maintainer
- [ ] В логах присутствует корректный prompt_sha256 для всех вызовов
- [ ] Все события llm_call_start/end логируются корректно
- [ ] Нет ошибок 5xx в логах

### Метрики
- [ ] Количество вызовов Maintainer увеличилось на количество тестов

- [ ] Нет fallback вызовов при нормальной работе
- [ ] Использование бюджета в пределах лимитов
