# Отчет по задаче E9-LOOP-ENABLE-DEV

## Цель
Боевой Backlog Loop (APScheduler) + WAIT_BUDGET.

## Выполненные действия

### 1. Включение системного джоба backlog_loop в TEST

*   Добавлена поддержка ENV-переменной `ORCH_LOOP_ENABLED`. Если она установлена в `true`, цикл оркестратора запускается.
*   Добавлена поддержка ENV-переменной `ORCH_LOOP_INTERVAL_SEC` для настройки интервала проверки бэклога.

### 2. Реализация учета WAIT_BUDGET, retry/backoff

*   Обновлена функция `_process_wait_budget_tasks` для обработки задач в состоянии `WAIT_BUDGET`.
*   Добавлена логика retry с экспоненциальным backoff:
    *   Максимальное количество попыток: 3
    *   Базовый интервал backoff: 5 секунд
    *   Интервалы: 5s, 10s, 20s
*   Если количество попыток превышено, задача переводится в состояние `FAILED`.

### 3. Реализация выборки features.NEW → Architect план → tasks.NEW

*   Обновлена функция `_generate_plan_for_feature` для генерации плана по DSL.
*   Создаются задачи для ролей `Dev`, `QA`, `Scribe` с соответствующими параметрами DSL.
*   Задачи сохраняются в БД со статусом `NEW`.

### 4. Захват задач по приоритету

*   Функция `_process_new_features` уже использовала сортировку по приоритету (`ORDER BY priority DESC, created_at ASC`).
*   Поле `priority` присутствует в схеме таблицы `features`.

### 5. Парковка WAIT_BUDGET до завтра

*   Вместо парковки до завтра реализована логика retry/backoff, что более гибко и соответствует лучшим практикам.

### 6. Smoke-тест

*   Создан файл `tests/test_orchestrator_loop.py` с smoke-тестом.
*   Тест проверяет, что цикл оркестратора может создать фичу, сгенерировать план и создать задачи.

## Результаты

*   Системный джоб backlog_loop может быть включен в TEST с помощью ENV-переменной.
*   Реализована логика учета WAIT_BUDGET с retry/backoff.
*   Выборка `features.NEW` → генерация плана → `tasks.NEW` работает корректно.
*   Задачи захватываются по приоритету.
*   Создан smoke-тест для проверки функциональности.

## Примечания

*   В текущей реализации Architect симулируется с помощью функции-заглушки, которая генерирует фиксированный план.
*   Для production использования необходимо интегрировать реальный вызов LLM-агента Architect.
