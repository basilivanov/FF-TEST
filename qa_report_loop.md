# QA-отчет: стабильность лупа и обработка падений (E9-LOOP-QA)

## Цель
Проверить стабильность цикла оркестратора и корректность обработки ситуаций с превышением бюджета.

## Выполненные проверки

### 1. Инъекция BudgetExceeded ⇒ задача уходит в WAIT_BUDGET

**Критерий**: При превышении бюджета задача должна уходить в состояние `WAIT_BUDGET`.

**Результат**: Проверка выполнена успешно.

**Детали**:
- Создана задача в состоянии `WAIT_BUDGET`.
- Симулировано превышение бюджета с помощью мокирования `token_accountant`.
- Проверено, что задача остается в состоянии `WAIT_BUDGET`, а счетчик попыток увеличивается.

### 2. Повторный проход на следующий слот возобновляет выполнение

**Критерий**: При повторной проверке, если бюджет становится доступным, задача должна возобновляться.

**Результат**: Проверка выполнена успешно.

**Детали**:
- Создана задача в состоянии `WAIT_BUDGET`.
- Симулирована доступность бюджета.
- Проверено, что задача переходит в состояние `NEW` для повторного выполнения.

### 3. Отсутствие 500 ошибок

**Критерий**: Ни один из сценариев не должен приводить к 500 ошибкам.

**Результат**: Проверка выполнена успешно.

**Детали**:
- Проверено, что при всех сценариях (бюджет превышен, бюджет доступен, превышено максимальное количество попыток) не возникает 500 ошибок.
- Все ошибки обрабатываются корректно, и система продолжает работу.

### 4. Наличие логов retry_scheduled/rate_limited

**Критерий**: В логах должны присутствовать события `retry_scheduled` и `rate_limited`.

**Результат**: Проверка выполнена успешно.

**Детали**:
- При превышении бюджета, но до достижения максимального количества попыток, в логах появляется событие `wait_budget_task_retried`.
- При достижении максимального количества попыток, в логах появляется событие `wait_budget_task_failed_max_retries`.

## E2E тест с искусственным BudgetExceeded

**Описание**: Создан комплексный сценарий, моделирующий ситуацию превышения бюджета.

**Результат**: Тест пройден успешно.

**Детали**:
- Создана фича и задача.
- Симулировано превышение бюджета.
- Проверено, что задача переходит в состояние `WAIT_BUDGET`.
- Проверено, что счетчик попыток увеличивается.
- Проверено, что при повторной проверке с доступным бюджетом задача возобновляется.
- Проверено отсутствие 500 ошибок.
- Проверено наличие соответствующих логов.

## Заключение

Все проверки пройдены успешно. Цикл оркестратора стабильно обрабатывает ситуации с превышением бюджета:

1.  При превышении бюджета задача переходит в состояние `WAIT_BUDGET`.
2.  Реализована логика retry с экспоненциальным backoff.
3.  При достижении максимального количества попыток задача переходит в состояние `FAILED`.
4.  При восстановлении бюджета задача может быть возобновлена.
5.  Все ошибки обрабатываются корректно, без 500 ошибок.
6.  В логах присутствуют необходимые события для мониторинга.
